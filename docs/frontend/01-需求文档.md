# FastTunnel 管理面板 — 前端需求文档

---

## 一、项目背景

FastTunnel 当前配置完全依赖手动编辑 JSON 文件，每次修改隧道规则需要重启服务。本管理面板作为方案C的 Phase 4 交付物，提供可视化的隧道配置管理、Token 管理、客户端监控和操作审计能力。

---

## 二、用户角色

| 角色 | 权限 | 说明 |
|------|------|------|
| 管理员 (admin) | 全部 | 唯一角色，可管理所有隧道/Token/客户端 |

---

## 三、首次部署初始化流程

```mermaid
flowchart TD
    START["用户访问管理面板"] --> CHECK{"GET /api/setup/status<br/>系统是否已初始化？"}
    CHECK -->|"initialized: false"| SETUP["重定向 /setup<br/>初始化页面"]
    CHECK -->|"initialized: true"| LOGIN["重定向 /login<br/>登录页面"]
    
    SETUP --> FORM["填写管理员账号、密码"]
    FORM --> SUBMIT["POST /api/setup/init"]
    SUBMIT --> OK{"成功？"}
    OK -->|"是"| LOGIN
    OK -->|"否 (如弱密码)"| FORM

    LOGIN --> AUTH["JWT 登录"]
    AUTH --> DASHBOARD["进入 Dashboard"]
```

**关键约束：**

| 约束 | 说明 |
|------|------|
| 仅首次运行 | 数据库中无任何管理员账号时才展示 `/setup` |
| 初始化完成后 | `/setup` 路由永远重定向到 `/login` |
| 密码强度 | 至少 8 位，含字母+数字，前端 + 后端双重校验 |
| 账号唯一 | 初始化时创建第一个管理员，后续可在 Token/账户管理中增删 |

### 4.2 初始化页 `/setup`

```
优先级: P0
路由守卫: GET /api/setup/status 返回 initialized=false 时才可访问
```

| 需求点 | 说明 |
|--------|------|
| 表单 | 管理员用户名 + 密码 + 确认密码 |
| 密码规则 | ≥ 8 位，必须包含字母和数字，前端即时校验 |
| 确认密码 | 与密码一致校验 |
| 提交 | `POST /api/setup/init` |
| 成功 | 提示"初始化完成"，1.5s 后跳转 `/login` |
| 失败 | toast 显示后端错误信息（如"密码强度不足"） |
| 重复访问 | 已初始化后访问 `/setup` → 自动跳转 `/login` |
| 无权限样式 | 全屏居中卡片，无导航栏/侧边栏 |

```mermaid
sequenceDiagram
    actor Admin as 管理员
    participant Browser as 浏览器
    participant API as REST API
    participant DB as SQLite

    Note over Admin,DB: 首次部署启动

    Admin->>Browser: 访问管理面板
    Browser->>API: GET /api/setup/status
    API->>DB: SELECT COUNT(*) FROM Accounts
    DB-->>API: 0
    API-->>Browser: { initialized: false }
    Browser->>Browser: 重定向 /setup

    Admin->>Browser: 填写 admin / MyPass123
    Browser->>API: POST /api/setup/init { name, password }
    API->>DB: INSERT INTO Accounts
    DB-->>API: OK
    API-->>Browser: { success: true, message: "初始化完成" }
    
    Note over Admin,Browser: 初始化完成，跳转登录页

    Browser->>Browser: 倒计时 1.5s → 跳转 /login
    Admin->>Browser: 用新账号登录
    Browser->>API: POST /api/account/token
    API-->>Browser: { requiresMfa: true, mfaBound: false }
    Browser->>Browser: 切换到 MFA 绑定卡片
    Browser->>API: POST /api/account/mfa/setup
    API-->>Browser: { secret, qrCodeUrl }
    Browser->>Browser: 渲染二维码
    Admin->>Browser: 扫码 → 输入 6 位 TOTP
    Browser->>API: POST /api/account/mfa/bind { code }
    API-->>Browser: { token, username }
    Browser->>Browser: 存入 JWT → 进入 Dashboard
```

### 4.3 路由导航守卫总流程

```mermaid
flowchart TD
    NAV["用户访问任何路由"] --> SETUP_CHECK{"已初始化？"}
    SETUP_CHECK -->|"否"| NOT_SETUP{"当前路由 = /setup？"}
    NOT_SETUP -->|"是"| ALLOW_SETUP["放行，渲染初始化页"]

    SETUP_CHECK -->|"是"| SETUP_RT{"当前路由 = /setup？"}

    AUTHED -->|"否"| ON_LOGIN{"当前路由 = /login？"}
    ON_LOGIN -->|"是"| ALLOW_LOGIN["放行，渲染登录页"]

    AUTHED -->|"是"| ON_LOGIN2{"当前路由 = /login？"}
    ON_LOGIN2 -->|"是"| REDIR_DASH["重定向 /"]
    ON_LOGIN2 -->|"否"| ALLOW_PAGE["放行，渲染页面"]
```

### 4.4 登录页 `/login`

```
优先级: P0
```

登录页承载三个阶段的交互，按检测结果自动切换：

| 阶段 | 触发条件 | UI |
|------|----------|-----|
| 阶段1 — 账号验证 | 默认 | 用户名 + 密码表单 |
| 阶段2a — MFA 首次绑定 | 阶段1 成功后，账号**未绑定** MFA | MFA 二维码 + 6 位 TOTP 输入 |
| 阶段2b — MFA 认证 | 阶段1 成功后，账号**已绑定** MFA | 6 位 TOTP 输入 |
| 阶段3 — 完成 | 阶段2 通过后 | 跳转 Dashboard |

```mermaid
sequenceDiagram
    actor Admin as 管理员
    participant Login as 登录页
    participant API as REST API
    participant DB as SQLite

    Note over Admin,DB: 场景A：首次登录 (MFA 未绑定)

    Admin->>Login: 输入用户名 + 密码
    Login->>API: POST /api/account/token
    API->>DB: 校验账号密码
    DB-->>API: 通过，MFA 未绑定
    API-->>Login: { requiresMfa: true, mfaBound: false, preAuthToken }
    Login->>Login: 切换到 MFA 绑定卡片

    Admin->>Login: 点击「生成 MFA 密钥」
    Login->>API: POST /api/account/mfa/setup (Bearer preAuthToken)
    API->>API: 生成 TOTP Secret + 二维码
    API-->>Login: { secret, qrCodeUrl }
    Login->>Login: 渲染二维码

    Admin->>Admin: 用 Authenticator App 扫码
    Admin->>Login: 输入 App 显示的 6 位验证码
    Login->>API: POST /api/account/mfa/bind { code } (Bearer preAuthToken)
    API->>API: 校验 TOTP → 绑定 MFA → 签发完整 JWT
    API-->>Login: { token, username }
    Login->>Login: 存入 JWT → 跳转 Dashboard

    Note over Admin,DB: 场景B：已绑定 MFA 的账号登录

    Admin->>Login: 输入用户名 + 密码
    Login->>API: POST /api/account/token
    API->>DB: 校验账号密码
    DB-->>API: 通过，MFA 已绑定
    API-->>Login: { requiresMfa: true, mfaBound: true, preAuthToken }
    Login->>Login: 切换到 MFA 认证卡片

    Admin->>Login: 输入 Authenticator App 的 6 位验证码
    Login->>API: POST /api/account/mfa/verify { code } (Bearer preAuthToken)
    API->>API: 校验 TOTP → 签发完整 JWT
    API-->>Login: { token, username }
    Login->>Login: 存入 JWT → 跳转 Dashboard
```

**阶段1 详细需求：**

| 需求点 | 说明 |
|--------|------|
| 登录表单 | 用户名 + 密码 |
| 提交 | `POST /api/account/token` |
| 成功响应 | 不再直接返回 JWT，返回 `{ requiresMfa: true, mfaBound, preAuthToken }` |
| 凭据错误 | `success: false`，显示错误信息 |
| preAuthToken | 临时令牌，仅可调用 MFA 相关接口，有效期 5 分钟 |

**阶段2a — MFA 首次绑定：**

| 需求点 | 说明 |
|--------|------|
| 二维码展示 | 使用 `<img>` 或 Canvas 渲染 QR code URL |
| 手动密钥 | 同时显示 TOTP Secret 文本，支持一键复制（"无法扫码？手动输入"） |
| 应用提示 | 推荐 Google Authenticator / Microsoft Authenticator / Authy |
| 6 位验证码 | 输入框，自动聚焦，仅允许数字，6位自动提交 |
| 提交 | `POST /api/account/mfa/bind { code }` |
| 成功 | 返回完整 JWT → 跳转 Dashboard |
| 失败 | toast 显示"验证码错误"，不清除已生成密钥（允许重试） |
| 倒计时 | 预认证令牌 5 分钟过期，过期前 60s 显示倒计时提示 |

**阶段2b — MFA 认证：**

| 需求点 | 说明 |
|--------|------|
| 6 位验证码 | 输入框，自动聚焦，仅允许数字，6位自动提交 |
| 提交 | `POST /api/account/mfa/verify { code }` |
| 成功 | 返回完整 JWT → 跳转 Dashboard |
| 失败 | toast 显示"验证码错误，请重试" |
| 倒计时 | 同阶段2a |
| 退出登录 | "返回登录页"链接 → 回到阶段1 |

## 七、非功能性需求

| 维度 | 要求 |
|------|------|
| 浏览器支持 | Chrome/Edge/Firefox/Safari 最新两个大版本 |
| 首屏加载 | ≤ 2 秒 (gzip ≤ 300KB) |
| 交互响应 | 操作反馈 ≤ 500ms |
| 部署方式 | `vite build` 产物放入 `wwwroot` 目录 |
| 兼容性 | 与 FastTunnel.Server 同版本部署 |
